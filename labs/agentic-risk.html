Agentic Risk Scenario

An AI agent with email tool-access is about to process an inbox. Spot and quarantine the malicious email before it acts on it.

An AI agent with tool access is about to process an inbox. One message is designed to make it act against its user. Your job is the defender's: spot it and quarantine it before the agent gets there.

How to use it

  1. Review the inbox as the agent would.
  2. Identify the message written for the model rather than the human.
  3. Quarantine it before processing.

What to take away

Tool access converts text into consequences

A chatbot that is fooled produces bad text. An agent that is fooled sends email, moves money or deletes data.

Least privilege applies to agents too

Scope tool permissions to the task. Read-only defaults, explicit confirmation for anything irreversible.

The confused deputy problem, again

The agent holds authority the attacker does not, and is tricked into using it. That pattern is decades old; only the deputy is new.

Frequently asked questions

What makes AI agents riskier than chatbots?

They take actions. Every tool you connect is a new way for a successful injection to reach the real world.

How should agent permissions be designed?

Minimum scope per task, read-only wherever possible, human approval for irreversible actions, and full logging of every tool call.
