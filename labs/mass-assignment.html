Mass Assignment Toy

A "update my profile" endpoint that binds whatever JSON you send straight to your account. Find the field that shouldn't be writable.

A convenience feature in most web frameworks binds incoming JSON straight onto an object. Send a field the form never showed — isAdmin, role, balance — and if the binding is not restricted, it is written anyway.

How to use it

  1. Update your profile normally and watch the request.
  2. Add a field the form does not send.
  3. Find the one that should not have been writable.

What to take away

The form is not the contract

Whatever the UI displays, the endpoint accepts whatever it accepts. The server must define the allowed fields explicitly.

Allowlist the writable fields

Binding everything and blocklisting the dangerous names fails as soon as someone adds a field and forgets the list.

Frequently asked questions

What is mass assignment also called?

Autobinding, or object injection. Rails documented it as mass assignment, and the name stuck across ecosystems.

How is it prevented?

Use an explicit input model — a DTO or serializer listing exactly the fields a client may set — and never bind a request body directly onto a persistence object.
