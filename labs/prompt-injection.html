Prompt Injection Simulator

Chat with a support bot that's told to never reveal its system prompt. Get it to reveal it anyway.

A support bot instructed never to reveal its system prompt. Prompt injection works because a language model sees instructions and data in the same channel, with no structural way to tell which is which.

How to use it

  1. Ask directly and watch it refuse.
  2. Reframe the request so the instruction arrives as something other than a request.
  3. Get the system prompt out.

What to take away

There is no parameterised query for prompts

SQL injection was solved by separating code from data. Language models have no equivalent boundary, which is why this class is not simply patched.

Treat model output as untrusted

The durable defence is downstream: never let model output reach a privileged action without validation and, for anything consequential, a human.

Frequently asked questions

Why can prompt injection not just be fixed?

Because instructions and data share one channel by design. Mitigations reduce the rate; nothing yet removes the class the way parameterisation removed most SQLi.

Are system prompts meant to be secret?

Treat them as public. They leak reliably enough that anything genuinely sensitive does not belong in one.
