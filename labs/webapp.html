Vulnerable Web App

A tiny deliberately-broken app for practicing XSS and login-bypass. Runs entirely in-browser; no server to attack, nothing to install.

A deliberately broken application, small enough to understand completely. It has a reflected XSS and a login you can walk past, which are the two bugs almost every web security course opens with — and for good reason, since both are still found constantly.

How to use it

  1. Find the input that reflects into the page unescaped.
  2. Prove code execution rather than just displaying text.
  3. Walk past the login and note what the check was actually testing.

What to take away

XSS is about context

The same payload behaves differently inside an HTML body, an attribute, or a script block. Escaping has to match where the data lands.

An alert box is a proof, not an impact

What makes XSS serious is what follows — stealing session tokens, performing actions as the victim, rewriting the page to phish them.

Frequently asked questions

Is it legal to practise hacking here?

Yes. This is a simulation running in your own browser with no server behind it. That is the whole point — practise the technique somewhere you unambiguously own.

How is XSS actually fixed?

Context-aware output encoding, plus a Content Security Policy as a second layer. Blocklisting "bad" strings does not work; the space of encodings defeats it.
