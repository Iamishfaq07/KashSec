Linux Privesc Playground

Enumerate SUID binaries on a simulated box and find the one GTFOBins turns straight into a root shell.

Enumerate SUID binaries on a simulated machine and find the one that GTFOBins turns into a root shell. SUID means "run as the file's owner", and a single unnecessary SUID binary is often the whole path to root.

How to use it

  1. List SUID binaries on the system.
  2. Identify the one that should not be there.
  3. Use its documented capability to become root.

What to take away

Many normal tools escalate when SUID

find, vim, less and awk can all run commands. Harmless normally; a root shell when SUID.

GTFOBins is the reference

It catalogues exactly how each binary can be abused for shell access, file read and file write. Both sides use it.

Check sudo too

sudo -l often reveals a permitted command that shells out — the same escalation by a different route.

Frequently asked questions

What does the SUID bit do?

Runs the program as its owner rather than as you. Necessary for a few tools like passwd; dangerous on anything that can execute arbitrary commands.

How do I find SUID binaries?

find / -perm -4000 -type f 2>/dev/null. Comparing that against a known-good baseline is what makes the result meaningful.
