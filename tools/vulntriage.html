Vulnerability Triage Practice

Work through fictional findings and choose evidence-led next steps for applicability, mitigation, and verification.

Practice making defensible vulnerability decisions using fictional cases. The exercise separates evidence that a vulnerability is exploited from evidence that your own deployed service is affected. It does not query a live vulnerability database or calculate risk for a real organization.

How to use it

  1. Choose one of the three fictional cases.
  2. Read the evidence and choose the next action.
  3. Check your reasoning and compare it with the explanation.
  4. Read the linked lessons and repeat with a different case.

What to take away

Confirm applicability

Find the version and configuration actually deployed on the affected asset. An inventory record or a catalog entry is a starting point, not proof that a particular service is vulnerable.

Look beyond severity

Consider exposure, reachability, observed exploitation, operational impact and uncertainty. A score is a useful input, but it does not make the decision for the asset owner.

Verify closure

A merged change is not necessarily deployed everywhere. Check the running build and relevant behavior, record what was tested, and identify remaining risk.

Frequently asked questions

Does this tool look up real CVEs?

No. The cases are fictional and run locally. Consult current vendor advisories and authoritative catalogs for real findings.

Does known exploitation prove my asset is affected?

No. It is an important signal to investigate; verify the version, configuration and exposure on the relevant asset.

Does a passing CI build prove remediation?

It is useful evidence but does not prove that the fix was deployed to every affected asset. Verify the deployed change and relevant behavior.
